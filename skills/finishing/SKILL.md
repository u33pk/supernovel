# 统稿与交付

已完成小说的最终审校和交付。跨章节验证、格式化和交付选项呈现。

**开始时宣布：** "我正在使用 finishing 技能来完成最终审校。"

## 何时使用

- 所有章节写作完成且批次审查通过
- 所有元审查显示无严重问题
- 用户说"完成"、"统稿"、"交付"时

## 预检

1. 读取 `story-bible.md` —— 全部部分
2. 读取所有批次总结
3. 读取所有元审查
4. 统计已写作总章数

## 流程

### 第 1 步：最终一致性扫描

快速但全面的跨章节检查：

- **角色名：** 全部章节中拼写是否一致？
- **地点名：** 同上
- **时间线：** 整体时间线是否一致？
- **属性完整性（如适用）：** 跨全部章节的最终数学验证
- **背包最终状态（如适用）：** 最终背包是否合理？
- **关系最终状态（如适用）：** 是否匹配计划的结局？

### 第 2 步：节奏审阅

按顺序读章节总结：

- 是否有连续 3+ 章相同强度的区间？
- 相对于重要性，是否有章节太长或太短？
- 高潮节奏是否合适（不仓促、不拖沓）？
- 结局是否让人感到实至名归？

### 第 3 步：伏笔最终审计

检查每个已埋设的伏笔：

- 每次埋设是否都已回收？
- 每次回收是否都有对应的埋设？
- 有没有孤立的埋设（埋了但没回收）？
- 有没有无来由的回收（回收了但没埋设）？

### 第 4 步：呈现交付选项

使用 AskUserQuestion 呈现以下选项：

```
全部章节已完成，一致性检查通过。你想要怎么处理？

1. 合并为完整稿件
   — 将所有章节合并为一个文件

2. 分章节保留
   — 保持当前的分章文件结构

3. 导出故事圣经
   — 将 story-bible.md 作为独立参考文档

4. 清理草稿和大纲
   — 保留最终稿件，删除中间草稿和大纲文件

5. 全部保留
   — 不删除任何文件
```

### 第 5 步：执行选择

**选项 1：合并为完整稿件**
- 按顺序拼接所有章节文件
- 添加含小说标题的扉页
- 添加目录
- 保存到 `docs/supernovel/final/[书名]-完整版.md`

**选项 2：保持分章**
- 报告："章节文件保留在 `docs/supernovel/drafts/`"

**选项 3：导出故事圣经**
- 复制 story-bible.md 到 `docs/supernovel/final/story-bible-final.md`
- 移除 [TBD] 标记（全部应已解决）
- 清理变更日志（只保留最终状态）

**选项 4：清理草稿**
- 保留 `docs/supernovel/final/` 和 `story-bible.md`
- 删除 `docs/supernovel/drafts/`
- 删除 `docs/supernovel/outlines/`
- 删除 `docs/supernovel/batch-summaries/`
- 保留 `docs/supernovel/meta-reviews/`（对系列续作有用）

**选项 5：全部保留**
- 报告："所有文件保留不变"

## 危险信号

- 跳过最终一致性扫描
- 不检查伏笔完成度
- 未经用户确认就删除文件
- 不提供所有交付选项
- 已知问题未修复就合并章节

## 关键原则

- **最终验证** —— 宣布完成前做最后一次检查
- **用户选择** —— 让用户决定保留什么
- **干净交付** —— 最终产品应该打磨好可以直接使用

## 技能衔接

**前置技能：** supernovel:consistency-check（最终批次审查通过）
**读取：** story-bible.md、所有批次总结、所有元审查
**输出：** 最终稿件、清理后的故事圣经、或保留的文件结构
