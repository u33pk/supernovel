# 写作（5 章批次制）

以 5 章为一个批次写作，严格遵循已批准的大纲和批次计划。这是散文写作阶段——所有规划已完成，现在执行。

**开始时宣布：** "我正在使用 drafting 技能来写作第 {N} 批（第 {X}-{Y} 章）。"

## 何时使用

- chapter-outlining 产出已批准的批次计划和章节大纲之后
- 用户说"开始写"、"写第 N 章"、"开始写作"时

## 预检

在写作任何批次之前：

1. 读取 `story-bible.md` —— **全部内容**：世界观、角色、属性、背包、关系、情节、风格
2. 读取本批的批次计划
3. 读取本批的全部 5 个章节大纲
4. 如果不是第一批：读取所有之前的批次总结
5. 如果有属性/背包：读取当前属性和背包表

**铁律：**

```
在读取故事圣经和批次计划之前，不得写任何散文。
```

## 批次写作流程

### 对每批 5 章：

```
1. 读取：story-bible.md + 批次计划 + 5 个章节大纲 + 所有之前的批次总结
   ↓
2. 写作：第 N 章（严格按大纲）
   ↓
3. 写作：第 N+1 章（严格按大纲）
   ↓
4. 写作：第 N+2 章（严格按大纲）
   ↓
5. 写作：第 N+3 章（严格按大纲）
   ↓
6. 写作：第 N+4 章（严格按大纲）
   ↓
7. 更新：story-bible.md（属性、背包、关系，如需要）
   ↓
8. 保存：章节 + 批次总结
   ↓
9. 调用：supernovel:consistency-check 进行批次审查
```

### 写作规则

**严格按大纲：**
- 按指定的场景顺序
- 按指定的角色（不得添加没有档案的角色）
- 按指定的冲突
- 按指定的情感弧线
- 不得"创意发挥"偏离大纲
- 如果大纲感觉不对，停下来问用户——不要自由发挥

**风格遵循（来自 story-bible.md Style 部分）：**

**铁律：全文风格必须与故事圣经中定义的写作风格一致。如果写着写着风格漂移了，停下来重新校准。**

- 按指定的视角（第一人称/第三人称有限/全知）
- 按指定的时态
- 按指定的描写密度

**风格一致性规则：**
- **句式风格：** 如果选定"冷峻克制"，就不要突然出现华丽的长排比句；如果选定"华丽繁复"，就不要突然变成短促的电报体
- **用词层次：** 口语化风格用短词、俗语；华丽风格用长词、意象。不要混搭
- **节奏感：** 大开大合风格长短句交替制造冲击；娓娓道来风格句长均匀、节奏平稳。每批开始前回顾风格定义，写完后自检是否漂移
- **叙事距离：** 冷峻风格保持与角色的距离（少写内心独白）；治愈风格贴近角色内心（多写感受）。不要在同一批内忽远忽近
- **情感表达方式：** 冷峻风格通过动作和环境暗示情感；华丽风格直接描写情感意象。选定方式后不要随意切换

**角色声音：**

**铁律：每个角色的对话必须让读者不看对话标签就能认出是谁。这不是建议，是硬性要求。**

- 每个角色必须按其档案中定义的说话方式说话
- 参考角色档案中的示例台词（覆盖平静、愤怒、亲密、危机四种情绪）
- 没有角色应该"听起来像"另一个角色
- 同一角色在不同情绪下说话方式可以有变化，但核心特征（用词习惯、句式长度、口头禅）保持一致
- 如果角色 A 的台词可以无缝安到角色 B 嘴里 → 说明角色声音设计失败，停下来重新校准
- 对话中禁止出现角色档案中未定义的口头禅或标志性用语
- 角色自言自语、内心独白也需要符合其说话方式——不要变成作者的叙述腔

**散文质量：**
- 展示而非讲述（情感场景）
- 变化句长（不要连续 10 个短句，也不要连续 10 个长句）
- 避免同一段落内重复用词
- 每段应有明确目的
- 对话应推进情节或揭示角色——不要填充空间

### 结尾多样性（关键）

每章结尾必须按章节大纲指定的结尾类型写。大纲指定"悬念"就写悬念，指定"安静节拍"就写安静节拍。

**永远不要：**
- 连续两章使用相同结尾类型
- 每章都以角色"睡着了"或"望着天空"结尾
- 用"然后一切都变了"式的模糊陈述结尾

### 写完每章后

保存到：`docs/supernovel/drafts/chapter-NN.md`

不要在批次内章节间暂停。写完全部 5 章后再做批次审查。

## 批次完成（5 章写完）后

### 第 1 步：更新 story-bible.md

全部 5 章写完后更新故事圣经：

**属性（如果有 needs_stats）：**
- 应用这 5 章中发生的属性变化
- 更新当前属性表
- 追加到属性变更日志

**背包（如果有 needs_inventory）：**
- 添加获得的物品，移除使用/丢失的物品
- 更新装备变化
- 追加到变更日志

**关系（如果有 needs_relationship_map）：**
- 更新含触发事件的关系变化
- 更新联盟/群体状态
- 追加到关系变更日志

**章节总结：**
在 story-bible.md 中为每章写总结：

```markdown
### 第 [N] 章：[标题]
- **视角：** [角色]
- **关键事件：** [2-3 个要点]
- **角色弧光进展：** [主角如何变化]
- **新增世界观细节：** [添加了什么新细节]
- **属性/背包变化：** [如适用]
- **关系变化：** [如适用]
```

### 第 2 步：写批次总结

创建批次总结文档：

```markdown
# 第 [N] 批总结：第 [X]-[Y] 章

## 发生了什么
[这 5 章的 2-3 段叙述性总结]

## 关键事件
- [事件 1]
- [事件 2]
- ...

## 批次结束时角色状态
| 角色 | 批次结束状态 | 弧光进展 |
|------|------------|---------|
| | | |

## 属性/背包变化（如适用）
[所有数值变化的总结]

## 关系变化（如适用）
[所有关系转变的总结]

## 伏笔状态
| 埋设 | 预期回收 | 状态 |
|------|---------|------|
| | | |

## 写作模式自检
[自检：我有重复任何模式吗？我变化了结尾吗？我给某个角色太多/太少的篇幅了吗？
**风格自检：** 全文风格是否与故事圣经中定义的一致？有没有漂移到"模型默认风格"？
**角色声音自检：** 每个角色的对话是否独特？有没有"角色 A 说的话可以无缝安到角色 B 嘴里"的情况？]
```

保存到：`docs/supernovel/batch-summaries/batch-N-summary.md`

### 第 3 步：调用一致性检查

批次完成后，调用 `supernovel:consistency-check` 审查批次。

## [TBD] 解决规则

章节大纲可能包含 `[TBD]` 项。必须在写作阶段解决：

- 遇到大纲中的 `[TBD]` 时停下来
- 向用户呈现上下文和选项
- 获得用户决定
- 更新大纲和 story-bible.md
- 继续写作

不得在未询问用户的情况下填写 `[TBD]`。

## 危险信号

- 不读 story-bible.md 就写散文
- 偏离已批准的大纲
- 连续章节结尾同类型
- 角色表现与档案不一致（说话/行为不匹配）
- 引入 story-bible.md 中没有的角色
- 批次后不更新属性/背包
- 跳过批次总结写作
- 未询问用户就填写 [TBD] 项
- "创意"添加大纲中没有的场景
- 每章相同的段落结构
- 全文风格漂移到"模型默认风格"（突然变华丽/突然变口语化）
- 角色对话可以互换（A 的台词安到 B 嘴里也成立）
- 同一角色在不同场景下说话方式差异过大（失去辨识度）

## 关键原则

- **大纲就是法律** —— 严格遵循；如果不对，问用户
- **风格一致** —— 遵循 story-bible.md 的 Style 部分
- **角色一致** —— 声音、行为、能力必须匹配档案
- **数字准确** —— 属性和背包必须反映实际事件
- **关系演变** —— 每批后更新，不只是最后更新
- **批次记忆** —— 写批次总结供未来元审查使用

## 技能衔接

**前置技能：** supernovel:chapter-outlining（提供批次计划和大纲）
**后续技能：** supernovel:consistency-check（审查每批）
**读取：** story-bible.md（全部）、批次计划、章节大纲、之前的批次总结
**更新：** story-bible.md（Stats、Inventory、Relationships、Chapter Summaries）
**输出：** docs/supernovel/drafts/chapter-NN.md、docs/supernovel/batch-summaries/batch-N-summary.md
