# 角色设计

设计所有主要角色的详细档案，然后写入故事圣经。

**开始时宣布：** "我正在使用 character-design 技能来设计角色。"

<HARD-GATE>
在所有主要角色都设计完毕并获得用户批准之前，不得调用 plot-architecture 或任何写作技能。每个出现超过一章的角色都必须在 story-bible.md 中有档案。
</HARD-GATE>

## 何时使用

- worldbuilding 产出经批准的 story-bible.md（World 部分）之后
- 用户说"设计角色"、"我需要角色"时
- 在 plot-architecture 之前（角色驱动情节，不是情节填充角色）

## 预检

1. 读取 `story-bible.md` —— 了解世界观，特别是力量体系
2. 读取概念文档 —— 注意类型标记：`needs_stats`、`needs_inventory`、`needs_relationship_map`
3. 这些标记决定需要初始化哪些额外模块

## 检查清单

1. **读取 story-bible.md 和概念** —— 了解世界观和标记
2. **设计主角** —— 完整档案，与用户确认
3. **设计对手/对抗力量** —— 完整档案
4. **设计关键配角** —— 每个有明确的故事功能
5. **映射角色关系** —— 角色之间的关系网
6. **初始化属性系统** —— 如果 `needs_stats: true`
7. **初始化背包/装备/技能** —— 如果 `needs_inventory: true`
8. **初始化关系网络** —— 如果 `needs_relationship_map: true`
9. **写入 story-bible.md** —— 编译所有角色数据
10. **用户审阅** —— 请用户在继续前审阅
11. **转入 plot-architecture** —— 调用 `supernovel:plot-architecture`

## 角色设计流程

### 第 1 步：主角（必须第一个）

详细设计主角。逐项呈现并获得用户确认：

- **姓名：**（如有含义/渊源则说明）
- **外貌：** 2-3 个标志性特征，不是全身描写清单。什么让人一眼就能认出 TA？
- **性格：** 3-5 个核心特质 + 1 个致命弱点。弱点至关重要——完美的角色很无聊。
- **背景故事：** 塑造 TA 成为今天这个人的关键经历。不是传记——只写重要的时刻。
- **核心欲望：** TA 最想要什么？
- **核心恐惧：** TA 最害怕什么？（通常与欲望互为镜像）
- **角色弧光：** 故事开始时 A 状态 → 故事结束时 B 状态。TA 经历什么根本性的变化？
- **说话方式/行为习惯：** 一种独特的说话或行为方式，让读者不用看对话标签就能认出这是谁。给一个示例台词。
- **致命弱点后果：** TA 的弱点如何在故事中造成问题？

使用 AskUserQuestion 确认每个主要属性。一次一个问题。

### 第 2 步：对手/对抗力量

以与主角相同的深度设计。关键要求：
- 对手必须是主角的**镜像或对立面**
- 必须有自己可以理解的动机（不是"为了邪恶而邪恶"）
- 其力量必须直接挑战主角的致命弱点
- 如果对抗力量不是人（自然、社会、内心挣扎），仍然要设计明确的规则和升级机制

### 第 3 步：关键配角

对每个配角，先回答一个核心问题：

> "这个角色为什么存在于这个故事中？"

如果答案是"让世界观感觉更真实"——删掉这个角色。配角必须服务于故事功能：

| 功能 | 描述 |
|------|------|
| **导师** | 引导主角，通常自己也有缺陷 |
| **催化剂** | 触发主角的变化 |
| **镜像** | 展示主角可能变成的样子 |
| **对比** | 通过差异突出主角的特质 |
| **杠杆** | 创造压力迫使主角行动 |
| **见证者** | 看到并反映主角的旅程 |

对每个配角设计：
- 姓名、外貌（简要）、性格（2-3 个特质）
- 故事功能（从上表选择）
- 与主角的关系
- 弧光：扁平角色也可以，但必须说明为什么是扁平的（例如"锚定角色，不变化"）

### 第 4 步：角色关系图

映射所有角色之间的关系：

```
[角色 A] --关系类型--> [角色 B]
```

对每段关系：
- 类型：恋人/兄弟/师徒/对手/盟友/上下级/陌生人→知己/等
- 当前状态
- 在故事中如何变化（如果已知）
- 紧张来源（如有）

### 第 5 步：初始化属性系统（如果 `needs_stats: true`）

**仅适用于有数值进阶系统的小说**（游戏小说、修炼、系统小说）。

对每个有属性的角色：

1. 根据 story-bible.md 中的力量体系定义初始属性
2. 创建属性表和当前值
3. 创建空的变更日志

规则：
- 属性必须源于世界观的力量体系规则
- 初始属性必须与角色背景匹配
- 留出成长空间（不要一开始就满级）

### 第 6 步：初始化背包/装备/技能（如果 `needs_inventory: true`）

对每个相关角色：

1. 列出初始装备（故事开始时 TA 拥有什么）
2. 列出初始技能/能力
3. 列出任何任务物品或重要财产
4. 创建空的变更日志

规则：
- 初始库存必须匹配角色的背景和资源
- 不要一开始就给主角太多东西（留出成长空间）
- 装备属性必须遵循 story-bible.md 中的力量体系品质分级

### 第 7 步：初始化关系网络（如果 `needs_relationship_map: true`）

对人际关系复杂的小说（多线恋爱、政治阴谋、联盟/背叛）：

1. 创建初始关系矩阵
2. 定义带细微差别的关系类型：
   - 不只是"朋友"——"渐行渐远的发小"
   - 不只是"敌人"——"互相尊重的对手"
3. 定义联盟/群体结构
4. 规划关系变化轨迹（将在 plot-architecture 中细化）

关系网络是**活文档**——每个章节批次后都会更新。

## 写入 story-bible.md

所有角色批准后，写入 story-bible.md：

```markdown
## 角色

### [角色姓名]
- **角色：** [主角/对手/配角]
- **外貌：** [2-3 个标志性特征]
- **性格：** [核心特质 + 致命弱点]
- **背景：** [关键塑造经历]
- **核心欲望：** [TA 最想要什么]
- **核心恐惧：** [TA 最害怕什么]
- **弧光：** [A 状态] → [B 状态]
- **说话方式：** [独特说话方式，示例台词]
- **故事功能：** [配角使用]
- **关键关系：** [谁，什么关系]

## 角色属性（如果 needs_stats）
[每个角色的属性表]

## 背包与技能（如果 needs_inventory）
[每个角色的装备、背包、技能]

## 关系网络（如果 needs_relationship_map）
[关系矩阵、联盟追踪]
```

## 铁律

```
在写作中引入的任何角色，如果没有在故事圣经中有档案，就是违规。
```

这意味着：
- 每个有台词的角色至少需要简要档案
- 每个出现超过一个场景的角色需要完整细节
- 群众、无名仆人等背景角色可豁免
- 如果写作中需要新角色，停下来先添加其档案

## 自检

1. 主角的弧光是否与概念的主题对齐？
2. 对手是否直接挑战主角的致命弱点？
3. 每个配角是否有明确的故事功能？
4. 有没有重复角色？（两个角色服务同一功能 → 合并它们）
5. 属性/库存是否匹配力量体系规则？
6. 对于关系复杂的小说，关系图是否有矛盾？

## 危险信号

- 主角没有致命弱点
- 对手"纯粹邪恶"没有可理解的动机
- 配角"就是存在"没有明确功能
- 两个角色服务同一目的
- 属性不匹配力量体系规则
- 初始库存太强（没有成长空间）
- 关系复杂的小说跳过关系映射
- 未经用户批准就进入 plot-architecture

## 关键原则

- **角色驱动情节** —— 先设计角色再设计情节结构
- **缺陷创造故事** —— 完美的角色没有故事可讲
- **质量胜于数量** —— 更少但精心设计的角色胜过很多浅薄的角色
- **关系是故事引擎** —— 最好的情节来自角色关系
- **属性是承诺** —— 一旦设定就约束后续写作；谨慎设定

## 技能衔接

**前置技能：** supernovel:worldbuilding（提供世界观上下文）
**后续技能：** supernovel:plot-architecture（用角色构建情节）
**更新：** story-bible.md（Characters、Stats、Inventory、Relationship Network 部分）
