# 一致性检查（双层审查）

验证每批 5 章与故事圣经的一致性。检测重复模式、事实错误和风格单调。每 5 批（25 章）对所有批次总结进行元审查。

**开始时宣布：** "我正在使用 consistency-check 技能来审查第 {N} 批章节。"

## 何时使用

- drafting 完成一批 5 章后
- revision 做了重大修改后
- 用户说"检查一致性"、"审查这批"、"有没有问题"时

## 双层审查系统

```
第 1 层：批次审查（每 5 章）
  → 对照 story-bible.md 和批次计划检查本批
  → 检测批次内重复和不一致
  → 更新 story-bible.md

第 2 层：元审查（每卷结束时 / 默认每 50 章）
  → 综合审查当前卷的所有批次总结
  → 检测跨批模式和风格漂移
  → 检查当前卷的故事弧进展
  → 验证伏笔进度表
  → 与宏观架构对比（分卷模式）
```

---

## 第 1 层：批次审查

### 预检

1. 读取 `story-bible.md` —— 全部部分
2. 读取本批的批次计划
3. 读取本批的 5 个章节大纲
4. 读取已写作的章节（全部 5 章）
5. 如果不是第一批：读取所有之前的批次总结

### 审查清单

#### 1. 事实一致性（对照 story-bible.md）

逐章对照故事圣经检查：

| 检查项 | 验证内容 |
|--------|---------|
| **角色** | 姓名拼写一致、年龄正确、外貌匹配 |
| **世界观** | 地名正确、地理一致、规则被遵循 |
| **力量体系** | 能力匹配已建立的规则，未发明新能力 |
| **时间线** | 事件顺序正确、时间引用一致 |
| **属性** | 数字匹配当前属性表（如适用） |
| **背包** | 角色不使用没有的物品（如适用） |
| **关系** | 态度匹配当前关系状态（如适用） |

#### 2. 重复检测（反偷懒）

这是关键。检查模型"偷懒"时重复的模式：

**句子级重复：**
- 跨章使用相同句子结构
- 相同过渡词（"然而"、"突然"、"就在这时"）
- 相同段落模式（每段都以角色名开头）

**结尾重复：**
- 连续章节使用相同结尾类型
- 相同的悬念结构
- 每章都以"角色睡着了"或"望着天空"结尾

**动作重复：**
- 同一角色跨章使用相同肢体语言
- 相同动词反复使用（皱眉、叹气、点头）
- 相同反应模式（每次惊讶 → 瞪大眼、每次生气 → 握拳）

**角色过度曝光：**
- 批次计划说变换角色但同角色出现在全部 5 章
- 配角完全缺席当应该在场时
- 视角角色总是独处（缺少互动多样性）

**模式检测表：**

| 模式类型 | 第1章 | 第2章 | 第3章 | 第4章 | 第5章 | 问题？ |
|---------|-------|-------|-------|-------|-------|--------|
| 结尾类型 | | | | | | |
| 开头类型 | | | | | | |
| 视角角色 | | | | | | |
| 主导情绪 | | | | | | |
| 对话比例 | | | | | | |
| 风格一致性 | | | | | | |
| 角色声音可辨识度 | | | | | | |

填入此表。如果任何行显示重复 → 标记为问题。

#### 3. 批次计划遵循度

将已写章节与批次计划对比：
- 计划的事件是否实际发生了？
- 节奏韵律是否匹配计划？
- 计划的伏笔操作是否执行了？
- 角色出场是否匹配计划？

#### 4. 角色一致性

对本批出现的每个角色：
- **声音：** 对话是否匹配档案中的说话方式？是否至少参考了 3 条示例台词中的语气特征？
- **行为：** 行动是否匹配性格特质？
- **弧光：** 发展是否按计划推进？
- **知识：** TA 是否只知道此时应该知道的？
- **能力：** TA 是否只使用实际拥有的能力？

**角色声音专项检查：**
- 拿掉对话标签后，能否通过说话方式分辨这是哪个角色？如果不能 → 角色声音不够独特
- 同一角色在本批不同场景中，说话方式是否一致？如果差异过大 → 角色声音不稳定
- 角色 A 的台词是否可以无缝安到角色 B 嘴里？如果是 → 角色声音设计失败，标记为"重要"问题

#### 5. 全文风格一致性

对照 story-bible.md Style 部分检查本批所有 5 章：

**风格漂移检测：**
- 句式是否与选定风格一致？（冷峻风格突然出现华丽排比 = 漂移）
- 用词层次是否一致？（口语化风格突然出现书面语 = 漂移）
- 叙事距离是否一致？（贴近角色内心突然变成上帝视角 = 漂移）
- 情感表达方式是否一致？（通过动作暗示突然变成直接抒情 = 漂移）
- 描写密度是否与定义一致？（约定简洁但写了几段环境描写 = 漂移）

**风格退化检测（模型默认风格回退）：**
- 是否出现典型的"AI 味"描写？（"不禁"、"缓缓"、"嘴角微微上扬"高频出现）
- 是否每段结尾都用总结性句子？
- 是否情感描写过于直白（"他感到一阵悲伤"而不是通过行为暗示）？
- 是否所有场景的描写密度完全相同（没有详略得当）？

如果发现风格漂移 → 标记为"重要"问题，需要在 revision 中重新校准

#### 6. 属性/背包准确性（如适用）

- 每次属性变化事件 → 验证数学正确
- 每次装备变化 → 验证旧物品移除、新物品添加
- 每次技能使用 → 验证角色确实拥有该技能及等级
- 战斗结果 → 验证在给定数字下是否合理

#### 7. 关系一致性（如适用）

- 角色 A 对角色 B 的态度必须匹配当前关系状态
- 如果背叛还没发生，角色不能表现得好像已经背叛了
- 联盟成员应表现得与群体成员身份一致
- 信任度应匹配关系网络中的当前状态

### 问题分级

| 严重度 | 定义 | 处理 |
|--------|------|------|
| **严重** | 与 story-bible.md 直接矛盾（已死角色复活、已毁城市完好、数字错误） | 必须修复才能继续 |
| **重要** | 角色性格不一致、时间线模糊、重复模式 | 应该修复才能继续 |
| **轻微** | 用词重复、节奏小波动、轻微风格不一致 | 记录在总结中，有时间再修 |

### 批次审查后

1. **修复严重问题** —— 调用 `supernovel:revision` 或内联修复
2. **修复重要问题** —— 同上
3. **记录轻微问题** —— 在批次总结中注明
4. **更新 story-bible.md** —— 如果审查发现了应追踪的新细节
5. **写/更新批次总结** —— 包含审查发现

## 第 2 层：元审查（每卷结束时）

### 触发时机

当前卷所有批次完成后触发。一次性模式下按固定间隔（每 5 批 / 25 章）触发。
分卷模式下，每卷结束时对当前卷的所有批次总结进行元审查。

### 元审查清单

#### 1. 故事弧进展

读取全部 5 个批次总结。检查：
- 主角的弧光是否在向 B 状态推进？
- 节奏（来自章节粗分）是否被遵循？
- 计划的转折点是否按时到达？
- 故事是否偏离了情节架构？（小偏离可以；大偏离需要讨论）

#### 2. 长期重复模式

跨 25 章检查：
- **角色主导：** 是否有角色出现在 80%+ 的章节中？
- **场景单调：** 是否大部分场景在同一地点？
- **冲突类型：** 是否每章都是同类型冲突？
- **情感范围：** 情感调色板是否太窄？
- **句式漂移：** 写作风格是否退化或变得单调？
- **风格漂移：** 全文风格是否偏离了故事圣经中定义的风格？有没有悄悄回退到"模型默认风格"？
- **角色声音漂移：** 各角色的说话方式是否还独特？有没有跨批趋同（所有角色说话越来越像）？

#### 3. 伏笔审计

检查伏笔追踪器：
- 计划的回收是否按进度进行？
- 有没有被遗忘的已埋伏笔？
- 有没有没有对应埋设的回收？
- 是否需要移动伏笔到更早/更晚的章节？

#### 4. 角色弧光审计

对每个主要角色：
- 在这 25 章中弧光推进了多少？
- 进展是太快、太慢还是刚好？
- 相对于其重要性，TA 的篇幅是否足够？
- 关系是否按计划演变？

#### 5. 属性/背包完整性（如适用）

跨 25 章的属性变化：
- 数字是否仍然内部一致？
- 力量缩放是否合理（没有突然跳跃）？
- 主角的成长节奏是否适合故事时间线？
- 是否积累了数学错误？

#### 6. 关系网络健康度（如适用）

跨 25 章：
- 所有计划的关系变化是否按进度发生？
- 有没有被遗忘的关系线索？
- 关系复杂度是否可控（不会太纠缠）？
- 角色态度是否匹配最新关系矩阵？

### 元审查输出

保存到：`docs/supernovel/meta-reviews/volume-N-meta-review.md`

```markdown
# 元审查 [N]：第 [1]-[25] 章

## 故事弧状态
[本卷故事是否在正轨上？与宏观架构的偏差程度？]

## 检测到的重复模式
[发现的跨批模式]

## 伏笔审计
[本卷伏笔的埋设/回收状态]

## 角色弧光进展
| 角色 | 本卷弧光进展 | 是否在正轨 | 备注 |
|------|------------|-----------|------|
| | | | |

## 关系网络状态（如适用）
[关系演变总结]

## 属性完整性（如适用）
[力量缩放评估]

## 建议
[对下一卷需要什么调整？]
```

## 危险信号

- 跳过重复检测表
- 不验证数字就接受"应该没问题"
- 把严重问题标记为重要以避免修复
- 不对照所有之前的批次总结检查（不只是最后一份）
- 因为"故事看起来没问题"就跳过元审查
- 发现新细节后不更新 story-bible.md
- 信任 drafting 技能的自评而不独立验证

## 关键原则

- **证据先于声明** —— 先运行检查，然后下结论
- **重复是敌人** —— 模型偷懒的第一信号
- **数字不会说谎** —— 属性/背包必须数学一致
- **关系必须演变** —— 动态故事中的静态关系 = bug
- **元审查发现漂移** —— 单批审查看不到长期模式

## 技能衔接

**前置技能：** supernovel:drafting（产出章节和批次总结）
**后续技能：** supernovel:revision（修复发现的问题），或 supernovel:drafting（下一批）
**读取：** story-bible.md、批次计划、章节大纲、所有之前的批次总结
**更新：** story-bible.md、批次总结
**输出：** 问题报告、元审查文档
