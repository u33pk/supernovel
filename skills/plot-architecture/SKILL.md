# 情节架构

设计完整的故事结构——主线、副线、转折点和角色弧光整合。这是后续一切的蓝图。

**开始时宣布：** "我正在使用 plot-architecture 技能来设计情节架构。"

<HARD-GATE>
在情节架构完全设计并获得用户批准之前，不得调用 chapter-outlining 或任何写作技能。每个主要转折点都必须定义。
</HARD-GATE>

## 何时使用

- character-design 产出经批准的角色档案之后
- 用户说"规划情节"、"设计故事结构"时
- 在 chapter-outlining 之前（结构先于细节）

## 预检

1. 读取 `story-bible.md` —— 特别是角色、世界观和力量体系
2. 读取概念文档 —— 注意主题、情感目标、预估篇幅
3. 检查 `needs_relationship_map: true` —— 如果是，规划关系轨迹

## 检查清单

1. **读取 story-bible.md 和概念** —— 了解角色、世界观、主题、预估篇幅
2. **选择规划模式** —— 根据篇幅选择一次性规划或分卷规划
3. **选择故事结构** —— 推荐并获得用户选择
4. **规划主线** —— 主要转折点，逐个获得确认
5. **规划副线** —— 每条线有主题、连接点和结局
6. **规划关系轨迹** —— 如果 `needs_relationship_map: true`
7. **章节粗分** —— 节奏和韵律规划
8. **自检** —— 检查断裂、死胡同、弧光缺口
9. **写入 story-bible.md** —— 编入 Plot 部分
10. **用户审阅** —— 获得批准后继续
11. **转入 chapter-outlining** —— 调用 `supernovel:chapter-outlining`

## 第 0 步：选择规划模式

根据预估篇幅，推荐不同的规划模式。使用 AskUserQuestion。

| 模式 | 适用范围 | 做法 |
|------|---------|------|
| **一次性规划** | 短篇(1-3万字)/中篇(3-10万字)/长篇(10-30章) | 一次性规划全部章节结构和转折点 |
| **分卷规划** | 长篇连载(30章以上)/几百章的网文 | 只规划宏观架构和第一卷的详细结构，后续卷在前一卷完成后逐卷规划 |

**分卷模式参数：**
- **每卷章数：** 默认 50 章，用户可自定义（如 30、80、100）
- 使用 AskUserQuestion 让用户确认每卷章数

**为什么分卷？**
- 几百章的小说一次性规划所有细节不现实，后期必然大量偏离
- 分卷允许根据已完成内容调整后续方向
- 伏笔可以分卷管理，每卷有独立的伏笔埋设/回收节奏
- 角色弧光可以分卷推进，每卷有阶段性目标

**分卷模式的关键区别：**
- 第 2-5 步（主线、副线、关系、章节粗分）只规划**当前卷**的详细内容
- 但必须有一个**宏观架构**（见下方），定义全书的整体走向
- 每卷完成后，回到 plot-architecture 规划下一卷

## 第 1 步：选择故事结构

根据类型和概念推荐结构。使用 AskUserQuestion。

| 结构 | 适用类型 | 核心特点 |
|------|---------|---------|
| **三幕结构** | 大多数类型，通用 | 设定 → 对抗 → 解决 |
| **英雄之旅** | 冒险、成长、奇幻 | 12 阶段单一神话 |
| **起承转合** | 东亚文学、日常系 | 反转驱动，不要求核心冲突 |
| **救猫咪(15节拍)** | 商业小说、类型小说 | 15 个精确节拍 |
| **多视角/编织式** | 史诗奇幻、政治小说 | 多条汇合的故事线 |
| **非线性** | 悬疑、文学、实验性 | 时间跳跃、不可靠叙事 |

让用户选择或提出自定义结构。参考 `structure-reference.md` 了解各结构详情。

## 第 2 步：宏观架构（分卷模式必做，一次性模式跳过）

**仅在分卷模式下需要此步。** 一次性模式直接进入第 3 步。

宏观架构定义全书的整体走向，不涉及具体章节细节：

```markdown
## 宏观架构

### 全书概要
[用 3-5 段话描述整个故事从头到尾的走向]

### 卷规划
| 卷 | 预估章数 | 核心冲突 | 主角弧光阶段 | 关键转折 |
|---|---------|---------|------------|---------|
| 第一卷 | 50 | [本卷核心冲突] | [A → 中间态1] | [本卷高潮] |
| 第二卷 | 50 | [本卷核心冲突] | [中间态1 → 中间态2] | [本卷高潮] |
| ... | ... | ... | ... | ... |
| 最终卷 | 50 | [最终冲突] | [中间态N → B] | [全书高潮] |

### 全书伏笔总表
| # | 伏笔内容 | 计划埋设卷 | 计划回收卷 | 状态 |
|---|---------|-----------|-----------|------|
| | | | | |

### 全书副线总表
| 副线 | 服务主题 | 跨越卷 | 汇入主线点 |
|------|---------|--------|-----------|
| | | | |
```

宏观架构只需要获得用户对整体走向的确认，不需要每个细节都敲定。
后续卷的具体内容在前一卷完成后才详细规划。

## 第 3 步：规划主线

**一次性模式：** 规划全书所有主要转折点。
**分卷模式：** 只规划当前卷的主要转折点。全书走向已在宏观架构中定义。

按选定结构，逐一走过每个主要转折点。对每个转折点：

1. **描述事件** —— 发生了什么
2. **解释影响** —— 如何改变主角的处境
3. **连接角色弧光** —— 如何推动主角走向 B 状态
4. **获得用户确认** —— 使用 AskUserQuestion

需要定义的关键转折点：

- **开篇钩子：** 第一个场景。如何在第一段抓住读者？
- **激励事件：** 什么打破了主角的日常世界？
- **第一幕转折点：** 什么迫使主角踏上旅程？
- **中点：** 一个改变一切的揭示或逆转。假胜利或假失败。
- **第二幕转折点：** 最黑暗的时刻。主角的最低点是什么？
- **高潮：** 最终对决。主角如何面对终极考验？
- **结局：** 新常态。世界和角色如何改变了？

对每个转折点问："这个事件如何推进主角的弧光？"如果答案不清晰，事件需要重新考虑。

## 第 3 步：规划副线

对每条副线回答：

1. **服务什么主题？**（副线从不同角度探索主题）
2. **在哪里与主线交汇？**（必须至少有一个交汇点）
3. **涉及哪些角色？**
4. **如何结束？**
5. **如果砍掉它会怎样？**（如果没有损失 → 砍掉）

**规则：**
- 与主线没有交汇点的副线 → 砍掉
- 不服务主题的副线 → 砍掉
- 没有结局的副线 → 要么规划结局，要么砍掉
- 处女作最多 3 条副线。越少越好。

## 第 4 步：规划关系轨迹（如果 `needs_relationship_map: true`）

对人际关系复杂的小说，规划关键关系如何演变：

对每段主要关系：
1. **起始状态**（来自 character-design）
2. **关键转折点** —— 在哪些章节/事件中关系发生变化？
3. **结束状态**
4. **什么驱动变化？**（误解、背叛、共同磨难、渐行渐远）

对联盟/背叛弧线：
1. **联盟形成** —— 何时、为何
2. **紧张点** —— 什么制造压力
3. **破裂点** —— 什么导致背叛/分裂
4. **后果** —— 如何影响所有当事人

将这些轨迹写成时间线，供 chapter-outlining 参考。

## 第 5 步：章节粗分

**一次性模式：** 规划全书节奏。
**分卷模式：** 只规划当前卷的节奏。

规划节奏韵律：

1. 估算总章数
2. 分配每个幕/段的章节范围
3. 标记哪些章节是**高强度**（动作、揭示、高潮）vs **低强度**（喘息空间、角色发展）
4. 确保节奏遵循：紧张 → 放松 → 紧张 → 放松（永远不要 3+ 章相同强度）
5. 标记**高潮章节**（需要更多篇幅和更紧凑的节奏）
6. 标记**过渡章节**（应该更短更快）

以表格形式呈现：

```markdown
| 幕 | 章节 | 强度 | 焦点 |
|---|------|------|------|
| 第一幕 | 1-5 | 中 → 高 | 设定、激励事件 |
| 第二幕上 | 6-12 | 高 → 低 → 高 | 上升动作、中点 |
| 第二幕下 | 13-18 | 高 → 最低 → 高 | 下降、最黑暗时刻 |
| 第三幕 | 19-23 | 最高 → 解决 | 高潮、尾声 |
```

## 第 6 步：自检

设计完完整情节后：

1. **弧光连续性：** 每个转折点是否推动主角走向 B 状态？
2. **副线汇合：** 所有副线是否与主线连接？
3. **死胡同检查：** 有无情节线索走进死胡同？
4. **伏笔需求：** 什么需要早埋以便后续回收？
5. **角色利用率：** 所有已设计的角色是否在情节中有使用？
6. **节奏：** 对于预估篇幅来说节奏是否可持续？
7. **关系轨迹一致性：** 关系变化是否有明确触发？

```markdown
## 情节

### 规划模式：[一次性/分卷]
### 每卷章数：[如适用，默认 50]
### 结构：[选定结构名称]

### 宏观架构（分卷模式）
[宏观架构内容，如适用]

### 当前卷主线（第 N 卷）
- **开篇钩子：** [描述]
- **激励事件：** [描述]
- **第一幕转折点：** [描述]
- **中点：** [描述]
- **第二幕转折点：** [描述]
- **高潮：** [描述]
- **结局：** [描述]

### 副线
#### [副线名称]
- **服务主题：** [探索什么主题]
- **主线连接：** [在哪里交汇]
- **涉及角色：** [谁参与]
- **结局：** [如何结束]

### 伏笔规划
| # | 需要埋设的 | 埋设章节/卷 | 回收章节/卷 | 状态 |
|---|-----------|-----------|-----------|------|
| | | | | |

### 关系轨迹（如适用）
[关系变化时间线，含触发事件]

### 章节粗分
| 幕 | 章节 | 强度 | 焦点 |
|---|------|------|------|
| | | | |
```

## 危险信号

- 不影响主角的转折点
- 与主线没有连接的副线
- 超过 3 条副线（太复杂，读者会迷路）
- 每条副线没有明确结局
- 关系变化没有触发事件
- 节奏均匀地紧张（没有喘息空间）
- 关系复杂的小说跳过关系轨迹规划
- 未经用户批准就进入 chapter-outlining

## 关键原则

- **角色驱动情节** —— 每个事件都应考验主角的弱点或推动弧光
- **副线服务主题** —— 不探索主题就砍掉
- **少即是多** —— 更少副线、更少角色、更紧凑的故事
- **先埋后收** —— 伏笔必须在写作前规划
- **节奏即韵律** —— 像呼吸一样交替强度
