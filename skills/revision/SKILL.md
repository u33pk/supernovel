# 系统性修改

修复一致性检查发现的问题，或改进散文质量。一次一个问题，绝不打包。每次修复都必须重新验证。

**开始时宣布：** "我正在使用 revision 技能来修改第 {N} 章的问题。"

## 铁律

```
一次修一个问题。每次修复后都要验证。
```

不要打包修复多个问题。不要在修复特定问题时"顺便改进"未标记的内容。

## 何时使用

- consistency-check 报告严重或重要问题后
- 用户要求风格/节奏变化时
- 用户说"修改这段"、"重写这里"、"修一下节奏"时
- 元审查建议调整后

## 预检

1. 读取一致性检查报告（带严重度的问题列表）
2. 读取受影响的章节
3. 读取 story-bible.md 的相关部分
4. 排优先级：严重 → 重要 → 轻微

## 流程

### 对每个问题：

```
1. 识别：到底哪里错了？（引用 章节:段落）
   ↓
2. 根因：为什么会发生？
   - 事实错误（与 story-bible.md 矛盾）？
   - 角色不一致（声音/行为错误）？
   - 重复模式（偷懒写作）？
   - 节奏问题（太快/太慢）？
   - 风格问题（措辞别扭）？
   ↓
3. 计划：修复这个问题的最小改动是什么？
   ↓
4. 应用：做出修改
   ↓
5. 验证：读结果。是否：
   - 修复了原始问题？
   - 没有破坏其他东西？
   - 与 story-bible.md 保持一致？
   - 保持了章节的情感弧线？
   ↓
6. 更新：如果修复改变了事实细节，更新 story-bible.md
```

### 修改类型

| 类型 | 改什么 | 不改什么 |
|------|--------|---------|
| **事实修正** | 错误细节 → 正确细节 | 其他一切 |
| **角色声音修正** | 对话重写以匹配档案 | 情节、事件 |
| **重复修正** | 句子结构多样化 | 内容、含义 |
| **节奏修正** | 场景长度调整 | 事件、角色 |
| **风格润色** | 措辞、流畅度 | 含义、内容 |
| **属性/背包修正** | 数字修正 | 叙事 |

### 规则

- **不改未标记的内容。** 如果一致性检查标记了第 3 段，不要也"改进"第 5 段。
- **保留作者的声音。** story-bible.md 的风格部分定义了声音。不要用你的偏好覆盖它。
- **每次修复后重新验证。** 在上下文中读修改后的段落。是否仍然流畅？
- **更新 story-bible.md。** 如果修复改变了事实细节（角色名拼写、地点名、属性值），更新故事圣经。
- **重新运行一致性检查。** 所有修复应用后，对受影响的章节重新运行一致性检查。

### 修改后

1. 列出所有修改
2. 对受影响的章节重新运行一致性检查
3. 如果所有问题已解决 → 继续下一批或下一章
4. 如果发现新问题 → 继续修改循环

## 危险信号

- 一次修复多个问题
- 修改未标记的内容
- 在修改过程中改变故事的声音或基调
- 修复后不重新验证
- 事实修正后不更新 story-bible.md
- 把散文改"更好"当问题是事实性的（范围蔓延）

## 关键原则

- **最小改动** —— 只修复损坏的部分
- **一次一个** —— 打包修复难以识别什么起了作用
- **始终验证** —— 每次修复都必须检查
- **圣经是真相** —— 如果修复与故事圣经矛盾，修复是错的

## 技能衔接

**前置技能：** supernovel:consistency-check（发现问题）
**后续技能：** supernovel:drafting（下一批）或 supernovel:finishing（全部完成）
**读取：** 一致性检查报告、受影响的章节、story-bible.md
**更新：** 受影响的章节、story-bible.md（如事实修正）
